# Режим «Рука» — YOLO-pose (v1.6.10; с v1.6.13 — слежение за ЛАДОНЬЮ)

Раньше «Рука» искала цвет кожи (HSV) и срабатывала на лицо, дерево, стены.
Теперь используется **Ultralytics YOLO-pose**
(<https://docs.ultralytics.com/tasks/pose>): модель находит людей и 17 ключевых
точек (COCO).

## Как работает

1. Кадр камеры -> `cv2.dnn` + `models/yolo11n-pose.onnx` (вход 320x320,
   PyTorch на роботе **не нужен**). Инференс каждый `POSE_FRAME_SKIP`-й кадр
   (v1.6.13: 2 — метки живут на каждом кадре стрима, CPU вдвое свободнее).
2. **Самая передняя рука** — ближайшая к камере. У моно-камеры нет глубины,
   поэтому оценка по масштабу: чем ближе человек, тем выше его рамка.
   Выбирается рука **самого ближнего человека**; из двух рук одного человека —
   **поднятая** (запястье выше локтя, `POSE_PREFER_RAISED`), затем более
   уверенная точка.
3. **v1.6.13 — цель слежения: центр ЛАДОНИ, а не запястье.** В COCO-17 точек
   пальцев нет, поэтому центр ладони оценивается геометрически: запястье +
   `POSE_PALM_EXTEND` (0.30) вектора «локоть → запястье» (ладонь ≈ треть
   предплечья от запястья). Затем точка **привязывается к реальному пятну
   кожи**: в квадрате вокруг расчётной позиции ищется HSV-блоб
   (`POSE_PALM_SNAP`, те же границы, что у старого HSV-режима) — если пятно
   найдено, целью становится его центр масс. Итог: камера держит середину
   кисти даже когда предплечье машет, и не гуляет по рукаву. На оверлее цель —
   перекрестие с подписью `PALM`, запястье — маленькая точка.
4. Камера (панорама и наклон) доворачивает так, чтобы ладонь была в центре
   кадра. **Колёса не двигаются.** P-регулятор: `HAND_TRACK_GAIN` (доля ошибки
   за тик), мёртвая зона `HAND_TRACK_DEADZONE_DEG`, предел шага
   `HAND_TRACK_MAX_STEP_DEG`, сглаживание цели `HAND_TRACK_EMA`. При потере
   руки камера держит положение `HAND_LOST_HOLD_S` секунд, затем сбрасывает
   сглаживание (режим остаётся включён).
5. Углы не выходят за лимиты серво (`SERVO_LIMITS`; с v1.6.14 наклон камеры
   БЕЗ лимита — полный ход 0..180°, рабочий диапазон при желании сужается
   в config.py).

Направления совпадают с ручным управлением: рука правее центра — панорама
уменьшается; рука выше центра — наклон растёт («вверх» = +, как стрелки в
панели). Если у вашей сборки серво зеркальны — `CAM_PAN_TRACK_DIR` /
`CAM_TILT_TRACK_DIR` = `-1` в `config.py`.

## Модель

`models/yolo11n-pose.onnx` (11 МБ) входит в архив прошивки; `setup.py` копирует
её в `/home/pi/models/`. Свою/другую модель экспортируйте **на ПК**:

```bash
pip install ultralytics onnx
python3 tools/export_pose.py --imgsz 320 --scp pi@<IP робота>
# то же вручную: yolo export model=yolo11n-pose.pt format=onnx imgsz=320 opset=12
```

`--imgsz` обязан совпадать с `POSE_INPUT_SIZE` в `config.py`. Нет файла —
в оверлее надпись `POSE MODEL NOT FOUND`, режим не двигает камеру.

## Дообучение под кисть (опционально, v1.6.13)

Комплектная модель обучена на людях: точек пальцев в COCO нет, ладонь
оценивается геометрией. Если нужна точность «по пальцам» — дообучите модель
на датасете разметки кисти (21 ключевая точка, раскладка MediaPipe).
Декодер робота распознаёт число точек автоматически: выход (N, 68) вместо
(N, 56) включает раскладку `hand21` — центр ладони = среднее MCP-точек
(5/9/13/17), код на роботе менять не нужно.

Обучение идёт ТОЛЬКО на ПК (GPU 8+ ГБ или Google Colab) — на роботе 800 МБ
ОЗУ для этого мало:

```bash
# на ПК
pip install ultralytics onnx onnxsim
python3 tools/finetune_pose.py --data hand-kpts.yaml --imgsz 320 --epochs 100
# готовый ONNX скопировать на робота:
scp runs/pose/hand21_finetune/weights/best.onnx pi@10.42.0.1:/home/pi/models/yolo11n-pose.onnx
sudo systemctl restart picarpro
```

Датасет — YAML в формате Ultralytics pose (`kpt_shape: [21, 3]`), 300–800
своих кадров в CVAT/Label Studio достаточно для слежения камеры. Готовые
размеченные наборы «hand keypoints» ищите на Roboflow/Kaggle с экспортом
«Ultralytics YOLO Pose». Прогон с другой входной сеткой не пройдёт: загрузчик
probe-прогоном проверяет вход (`POSE_INPUT_SIZE`) и отбраковывает чужой.

## Ограничения (честно)

* COCO-pose даёт запястья, а не пальцы: центр ладони — геометрическая оценка
  + привязка к пятну кожи (v1.6.13). Точная точность «по пальцам» — только
  через дообучение (раздел выше).
* Рука видна, только если в кадре виден человек (хотя бы предплечье); для
  привязки к коже нужно, чтобы кисть была освещена (границы HSV настраиваются
  через старые параметры hand-цвета в панели).
* «Передняя» — оценка по размеру человека, а не измеренная глубина: если человек
  стоит дальше, но тянет руку вперёд, ближайшим будет всё равно другой, больший в кадре.
* Обновления сервопривода 2–4 Гц (инференс каждый `POSE_FRAME_SKIP`-й кадр,
  v1.6.13 = 2). Стрим при этом 30 fps: метки рисуются на каждом свежем кадре.
  Если камера «раскачивается» — уменьшите `HAND_TRACK_GAIN`; если ладонь
  теряется в движении — верните `POSE_FRAME_SKIP = 1` в `config_local.py`
  (CPU дороже). Нужно хорошее освещение.
